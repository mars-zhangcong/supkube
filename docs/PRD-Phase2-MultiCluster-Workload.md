# SupKube Phase 2 — 多集群工作负载管理（Veeam VBR 风格）产品需求文档 (PRD)

## 概述

- **产品名称：** SupKube
- **版本：** Phase 2 — Multi-Cluster Workload Management
- **目标：** 把 SupKube 从「单集群 Velero UI」升级为「集中式多集群数据保护平台」，用 **Veeam VBR 风格的工作负载（Workload）管理模型** 替代当前仿照 Kasten 的集群添加/管理方式
- **技术栈：** Go + Gin（后端，新增多集群控制面）、Vue 3 + Element Plus（前端）、Helm Chart（部署）；每个受管集群内 Velero 仍作为数据搬运代理（data mover）
- **目标用户：** 备份管理员、平台/SRE 团队、MSP（同时管理多个集群/多租户的运维）
- **参考产品：** Veeam Backup & Replication（受管服务器清单 + 作业模型）

---

## 一、方案评估与决策

### 1.1 两种模型对比

| 维度 | Kasten Multi-Cluster Manager（当前仿照） | Veeam VBR Workload 模型（建议采用） |
|------|------------------------------------------|--------------------------------------|
| 控制面 | **联邦式**：每个集群独立安装完整 K10，选一个 promote 为 Primary，其余用 join token 加入 | **集中式**：一个 SupKube Server 作为唯一控制面，其余集群作为「受管对象」注册进来 |
| 集群接入方式 | 集群内先装 K10 → Promote/Join Token → 二次确认加入 | 「添加集群」向导：填名称 + 凭据（kubeconfig / ServiceAccount Token）→ 校验 → 自动纳管 |
| 管理对象 | 以「集群」为中心，跨集群操作需 click-through 进入各 Secondary 仪表盘 | 以「**工作负载**」为中心：跨集群统一清单（Cluster → Namespace → Workload），单一视图操作 |
| 备份的基本单元 | 各集群内独立的 Backup / Schedule CRD | **备份作业（Job）**：一个作业可跨命名空间、跨集群选取一批工作负载，统一调度/保留/存储库 |
| footprint | 重（每个集群一套完整控制面 + UI） | 轻（受管集群只需 Velero 代理，控制面集中） |
| 新集群上手成本 | 高（安装 + promote/join + token 过期重试） | 低（一个向导、几分钟纳管） |
| 故障域 | 好（各集群自治，Manager 挂掉不影响本地备份） | 中（控制面是关键依赖，需 HA / 凭据安全） |
| 备份管理员心智模型 | 偏「集群运维」视角 | 偏「保护哪些业务负载」视角（与 Veeam/NetBackup 一致，备份团队更熟悉） |

### 1.2 决策：采用 Veeam VBR 风格的集中式工作负载模型

**理由：**

1. **贴合目标用户心智。** 备份管理员关心的是「哪些业务被保护了」，而非「每个集群里有哪些 CRD」。Veeam 的「清单（Inventory）→ 作业（Job）」模型是备份行业事实标准，学习成本最低。
2. **接入体验显著更优。** Kasten 的 Promote/Join Token 流程要求每个集群先部署完整控制面，且 token 会过期、需二次确认——正是当前「不方便」的根因。改为「填凭据即纳管」的向导后，新集群上手从「装一套 K10」降到「几分钟一个向导」。
3. **单一视图、批量操作。** 一个备份作业即可同时覆盖多集群的多个命名空间，无需逐集群进入。这对管理 5+ 集群的团队是数量级的效率提升。
4. **与 Velero 架构兼容。** Velero 本就是「集群内数据搬运器」。SupKube 把 Velero 降级为「代理」，控制面集中编排（下发 Backup/Schedule CRD、聚合状态），既保留 Velero 生态，又获得集中管理体验。

**保留的 Kasten 优点（通过设计弥补集中式的短板）：**

- 受管集群本地的 Velero 仍可在控制面离线时独立完成已下发的 Schedule（作业定义下沉为集群内 CRD，控制面只做编排与聚合，不在数据路径上）。
- 控制面支持 HA 部署与凭据加密存储，降低「单点依赖」风险。

> 本 PRD 的全部页面与用户故事均基于此决策展开。Phase 2 聚焦**多集群纳管 + 工作负载清单 + 作业模型**三大支柱；单集群的备份/恢复核心流程沿用 Phase 1。

## 二、术语映射（Veeam → SupKube）

| Veeam VBR 概念 | SupKube 对应概念 | 底层实现 |
|----------------|------------------|----------|
| Backup Server | SupKube Server（控制面） | Go 控制面 + 多集群客户端池 |
| Managed Server / Virtual Infrastructure | Managed Cluster（受管集群） | kubeconfig / ServiceAccount + client-go |
| Credentials Manager | Credentials（凭据库） | 加密存储的 Secret |
| Inventory（VMs） | Workload Inventory（工作负载清单） | 跨集群命名空间 / 工作负载发现 |
| Backup Job | Backup Job（备份作业） | 编排为各集群内的 Velero Backup/Schedule |
| Backup Repository | Repository（备份存储库） | Velero BackupStorageLocation（可跨集群共享） |
| Job Session / History | Job Session（作业会话） | 聚合各集群 Backup 执行结果 |
| Backup Proxy | Velero 实例（集群内代理） | 集群内 Velero Deployment |

## 三、功能范围（Phase 2）

聚焦集中式多集群与工作负载作业模型：

- 多集群纳管（添加/校验/纳管向导，替代 Promote/Join Token）
- 凭据集中管理
- 跨集群工作负载清单
- 备份作业（跨集群多工作负载选择 + 调度 + 保留）
- 共享备份存储库
- 多集群全局仪表盘
- 作业会话与历史
- 跨集群恢复

## 页面 1：Managed Clusters（受管集群）

**功能描述：** 集中式控制面的核心入口，列出并纳管所有受管 Kubernetes 集群。对标 Veeam「Managed Servers / Virtual Infrastructure」节点。**用「添加集群向导」彻底替代 Kasten 的 Promote / Join Token 流程。**

**用户故事：**
- US-1.1 [P0] 作为备份管理员，我希望看到所有受管集群列表（名称、API 地址、K8S 版本、连接状态、Velero 状态、工作负载数、最后同步时间），以便掌握全局基础设施
- US-1.2 [P0] 我希望通过「添加集群向导」用名称 + 凭据快速纳管一个新集群，无需在目标集群里预装完整控制面
- US-1.3 [P0] 我希望向导在纳管前**校验连接与权限**（能连通 API、能列资源、Velero 是否就绪），并给出明确的失败原因
- US-1.4 [P0] 我希望对未安装 Velero 的集群，由 SupKube 引导/一键安装 Velero 代理
- US-1.5 [P1] 我希望编辑集群（重命名、更换凭据、刷新清单）和移除集群（从纳管中解绑，不删除集群内数据）
- US-1.6 [P1] 我希望给集群打标签/分组（如 prod / staging、按地域），用于作业范围与筛选

**添加集群向导（Add Cluster Wizard）步骤：**
1. **Name & Description** — 集群显示名（RFC1123）、描述、标签
2. **Connection** — 接入方式：① 上传 kubeconfig；② API Server 地址 + ServiceAccount Token + CA。可选指定从凭据库复用的凭据
3. **Validate** — 实时校验：连通性、RBAC 权限（list/watch 资源、操作 Velero CRD）、K8S 版本兼容性
4. **Velero** — 检测 Velero：已就绪则展示版本；未安装则提供「一键安装」或跳过
5. **Summary** — 确认信息并完成纳管

**验收标准：**
- 列表显示：名称、标签、API 地址、K8S 版本、连接状态（Connected/Degraded/Unreachable）、Velero 状态（Ready/Not Installed/Error）、工作负载数、最后同步时间
- 向导每一步均可前进/后退；Validate 步骤失败时阻止继续并显示具体错误（权限/网络/版本）
- 纳管成功后 60 秒内完成首次工作负载清单同步
- 凭据**加密存储**，UI 不回显明文 token
- 移除集群仅解绑纳管关系，**不删除**集群内 Velero 备份数据，并需二次确认
- 连接状态后台周期探活（默认 60s），状态变化反映到仪表盘

## 页面 2：Credentials（凭据管理）

**功能描述：** 集中存储与复用集群接入凭据。对标 Veeam「Credentials Manager」。

**用户故事：**
- US-2.1 [P0] 作为备份管理员，我希望集中管理 kubeconfig / ServiceAccount Token 凭据，在纳管多个集群时复用
- US-2.2 [P0] 我希望看到每条凭据被哪些集群引用，避免误删
- US-2.3 [P1] 我希望更新凭据（如轮换 token）后，引用它的集群自动生效
- US-2.4 [P2] 我希望为凭据设置到期提醒

**验收标准：**
- 列表：凭据名称、类型（kubeconfig / SA Token）、描述、被引用集群数、创建/更新时间
- 凭据明文仅写入、不回显；存储为加密 Secret
- 删除被引用的凭据需先解绑或阻止删除并提示引用方
- 更新凭据后，引用集群的下一次探活使用新凭据

## 页面 3：Workload Inventory（工作负载清单）

**功能描述：** 跨所有受管集群的统一工作负载视图，以「工作负载」而非「集群」为中心。对标 Veeam「Inventory」。这是备份管理员选择保护对象的主入口。

**用户故事：**
- US-3.1 [P0] 作为备份管理员，我希望以树形结构浏览 **Cluster → Namespace → Workload**，跨集群一屏掌握所有可保护对象
- US-3.2 [P0] 我希望看到每个工作负载/命名空间的保护状态（已保护/未保护）、所属备份作业、最后备份时间
- US-3.3 [P0] 我希望按集群、标签、命名空间、保护状态、名称进行搜索与筛选
- US-3.4 [P0] 我希望多选工作负载后「添加到备份作业」或「新建备份作业」
- US-3.5 [P1] 我希望查看工作负载详情（包含的资源类型、PVC、关联的 Hooks）
- US-3.6 [P1] 我希望用动态规则（标签选择器 / 命名空间通配）定义工作负载集合，新建对象自动纳入保护

**验收标准：**
- 清单按 Cluster → Namespace → Workload 三级展示，支持懒加载与展开/折叠
- 每行显示：名称、类型（Deployment/Statefulset/Namespace 等）、所属集群、保护状态、所属作业、最后备份时间
- 离线/不可达集群的工作负载显示「数据可能过期」标记并显示最后同步时间
- 多选后可一键「Add to Job / New Job」，目标作业表单自动带入所选对象
- 筛选条件可组合，结果实时刷新

## 页面 4：Backup Jobs（备份作业）⭐ 核心范式

**功能描述：** Veeam 模型的核心——以「作业」为备份的基本单元。一个作业可跨集群、跨命名空间选取一批工作负载，统一配置调度、保留与存储库。对标 Veeam「Backup Job」。**这是相对 Kasten「逐集群、逐 CRD」模型的关键体验升级。**

**用户故事：**
- US-4.1 [P0] 作为备份管理员，我希望创建一个备份作业，从工作负载清单中（跨集群）选取保护对象
- US-4.2 [P0] 我希望为作业配置调度（Cron + 可视化：每天/每周/每月）、保留策略（数量或天数）、目标存储库
- US-4.3 [P0] 我希望看到作业列表（名称、对象数、覆盖集群、调度、最近结果、下次运行、状态）
- US-4.4 [P0] 我希望「立即运行（Run Now）」一个作业，并查看实时进度
- US-4.5 [P0] 我希望启用/禁用、编辑、删除作业
- US-4.6 [P1] 我希望作业内按集群查看各自的子任务（per-cluster sub-task）状态与日志
- US-4.7 [P1] 我希望配置作业级选项：快照模式（Filesystem / CSI）、Pre/Post Hooks、并发度
- US-4.8 [P2] 我希望作业失败时按集群粒度重试，而非整作业重跑

**作业创建向导：**
1. **Name** — 作业名称、描述、标签
2. **Workloads** — 从清单选取对象（支持静态选择 + 动态规则），可跨集群
3. **Storage** — 选择目标存储库（每集群解析到对应 BSL）
4. **Schedule** — Cron / 可视化调度，或「仅手动」
5. **Retention & Options** — 保留策略、快照模式、Hooks、并发度
6. **Summary** — 确认并（可选）立即运行

**验收标准：**
- 作业列表：名称、对象数、覆盖集群数、调度规则、最近会话结果（Success/Warning/Failed）、下次运行时间、状态（Enabled/Disabled）
- 作业落地为**各覆盖集群内的 Velero Schedule/Backup CRD**；控制面负责拆分（fan-out）与状态聚合（fan-in）
- 一个作业的运行产生一个**作业会话（Session）**，会话内含每集群子任务；任一子任务失败，会话标记为 Warning/Failed 并定位到具体集群
- Run Now 后实时刷新进度；完成后列表与会话历史更新
- 禁用作业即暂停对应集群内 Schedule（paused=true），不删除历史备份
- 删除作业需二次确认，并询问是否保留已产生的备份

## 页面 5：Repositories（备份存储库）

**功能描述：** 集中管理可被多集群作业共享的备份存储目标。对标 Veeam「Backup Repository」。在 Phase 1 单集群 Storage Locations 基础上扩展为多集群可共享。

**用户故事：**
- US-5.1 [P0] 作为备份管理员，我希望集中查看所有存储库及其连接状态、容量使用
- US-5.2 [P0] 我希望添加 S3 兼容存储库，并指定其可被哪些集群使用
- US-5.3 [P0] 我希望在创建作业时从存储库下拉选择目标
- US-5.4 [P1] 我希望设置默认存储库，并验证连接
- US-5.5 [P2] 我希望看到存储库的备份占用与对象数统计

**验收标准：**
- 列表：名称、Provider、Bucket、关联集群、状态（Available/Unavailable）、容量/对象数、是否默认
- 存储库在每个关联集群内解析为 BackupStorageLocation + Secret
- 添加表单：名称、Provider、Bucket、Region、Endpoint、Access/Secret Key、适用集群（多选）
- 30 秒内反馈各关联集群的连接状态
- 删除需确认无关联作业/备份

## 页面 6：Multi-Cluster Dashboard（多集群全局仪表盘）

**功能描述：** 集中式控制面的全局视图，跨集群聚合保护态势。对标 Veeam 概览面板。

**用户故事：**
- US-6.1 [P0] 作为备份管理员，我希望看到全局概览（受管集群数、工作负载总数、受保护数/未保护数、作业数）
- US-6.2 [P0] 我希望看到最近 24 小时作业会话结果汇总（成功/告警/失败）
- US-6.3 [P0] 我希望看到需要关注的项（不可达集群、失败作业、未保护的关键工作负载）
- US-6.4 [P1] 我希望按集群/标签下钻查看局部态势
- US-6.5 [P1] 我希望看到跨集群存储用量趋势

**验收标准：**
- 顶部卡片：集群数、工作负载数、保护率（%）、作业数、24h 会话成功率
- 「需关注」面板列出不可达集群、Failed/Warning 会话，可点击跳转定位
- 数据每 30 秒自动刷新；不可达集群以降级态展示并标注最后同步时间
- 任一卡片可下钻到对应列表页并自动带入筛选

## 页面 7：Job Sessions（作业会话与历史）

**功能描述：** 作业每次运行的执行记录与下钻。对标 Veeam「Session History」。

**用户故事：**
- US-7.1 [P0] 作为备份管理员，我希望查看作业会话历史（作业名、开始/结束时间、结果、对象数、数据量）
- US-7.2 [P0] 我希望展开会话查看每集群子任务的状态与统计
- US-7.3 [P0] 我希望查看子任务日志（通过 Velero DownloadRequest）以排障
- US-7.4 [P1] 我希望按作业、集群、结果、时间范围筛选会话
- US-7.5 [P2] 我希望导出会话报告

**验收标准：**
- 会话列表：作业、触发方式（Scheduled/Manual）、开始/结束、耗时、结果、对象/数据量
- 展开显示 per-cluster 子任务：集群、状态、对象数、错误信息
- 失败子任务可查看 Velero 备份日志
- 列表支持按作业/集群/结果/时间筛选，默认按时间倒序

## 页面 8：Restores（跨集群恢复）

**功能描述：** 从任意受管集群的恢复点恢复数据，支持原集群恢复与跨集群恢复。扩展 Phase 1 的单集群恢复。

**用户故事：**
- US-8.1 [P0] 作为备份管理员，我希望浏览全局恢复点（按作业/集群/工作负载/时间），并选择恢复点发起恢复
- US-8.2 [P0] 我希望恢复前预览将要恢复的资源
- US-8.3 [P0] 我希望恢复到**原集群原命名空间**（Phase 2 基础场景）
- US-8.4 [P1] 我希望**跨集群恢复**：将集群 A 的恢复点恢复到集群 B（前提：目标集群可访问同一存储库）
- US-8.5 [P1] 我希望查看全局恢复历史（状态、来源、目标、时间）
- US-8.6 [P2] 我希望恢复时做资源转换（StorageClass 映射、命名空间重映射、镜像仓库替换）

**验收标准：**
- 恢复点列表跨集群聚合，显示来源作业/集群/工作负载/时间/存储库
- 跨集群恢复要求目标集群已纳管且能访问来源存储库；不满足时给出明确提示
- 恢复落地为目标集群内的 Velero Restore CRD，状态实时回传
- 恢复历史：名称、来源备份、来源集群、目标集群、状态、时间、资源数
- 失败显示错误信息与日志

## 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 控制面列表页加载 < 3s；单集群 API 代理响应 < 1s；50 个受管集群规模下仪表盘聚合 < 5s |
| 扩展性 | 支持至少 50 个受管集群、单作业覆盖至少 10 个集群（MVP 目标；架构不应硬性受限） |

| 安全 | 凭据加密存储（at-rest）；UI 不回显 token；控制面到集群通信使用最小权限 RBAC；Phase 2 引入控制面 RBAC（管理员/操作员/只读） |
| 弹性 | 单集群不可达不影响其他集群的作业与展示；探活与重试有退避策略 |

| 可观测 | 控制面与各集群子任务有结构化日志；关键操作可审计 |
| 迁移 | Phase 1 的单集群安装可平滑「自纳管」为受管集群之一，历史备份不丢失 |
| 国际化 | Phase 2 英文优先，中文随后 |

## 附录：与 Phase 1 的关系

- Phase 1（单集群、Kasten K10 风格 UI）保留为「单集群快速上手」形态；其核心备份/恢复表单在 Phase 2 中作为作业/恢复向导的底层能力复用。
- Phase 2 的关键转变是**控制面从「集群内」上移到「集群外集中部署」**，并把交互重心从「集群/CRD」转为「工作负载/作业」。
- 现有单集群部署通过「自纳管」成为受管集群之一，实现平滑升级，不破坏既有备份数据与命名规则（沿用 v0.5.2 的 RFC1123 校验）。
