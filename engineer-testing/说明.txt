📚 三、 知识库大纲（RAG 数据）
这是AI的“专业内功”，决定了评分标准和分析深度。需要把这些内容写入向量库（Markdown/Text格式），作为Prompt上下文注入。
🟦 分类1：灾备原理与黄金法则 (DR Principles)
定义什么是“好的保护”，AI的核心判断标准。
1. 3-2-1 黄金法则：
数据必须有3份副本、存于2种不同介质、至少1份离线/异地存储。违反则风险极高。
2. RTO & RPO 定义：
• RTO (恢复时间目标)： 业务允许中断的最长时间。核心交易 < 15min；一般业务 < 4h；开发测试 < 24h。

• RPO (恢复点目标)： 业务允许丢失的数据量。核心交易 < 5min；一般业务 < 24h；开发测试 无要求。
3. 数据一致性原则：
• 数据库（MySQL, PG, Oracle）：必须使用一致性快照 + 事务日志备份（Binlog/WAL），仅文件快照无法保证一致性。

• 分布式系统（Mongo Shard, Kafka Cluster）：必须全局一致性备份，单节点备份无意义。

• 无状态服务（Nginx, NodeJS）：数据可重建，仅需配置备份，无需数据备份。
4. 备份存储原则：
• ❌ 禁止：备份与生产数据存于同一PVC/同一存储池/同一可用区。（一锅端风险）

• ✅ 推荐：生产SSD → 备份S3/对象存储 → 归档冷存储/离线磁带。
5. 验证原则：
• 备份了 ≠ 能恢复。 长期不做恢复演练（>6个月）的备份，视为无效备份，风险等同于无备份。

• 完整性检查 ≠ 可恢复性检查。必须定期执行恢复测试。
🟩 分类2：应用特征库（Application Knowledge Base）【重中之重】
AI“理解”软件的核心，不同软件有不同的评分标准和保护要求。
🔹 关系型数据库 (RDBMS)

• MySQL / MariaDB：
• 重要度权重：⭐⭐⭐⭐⭐ (极高)

• 数据特性：结构化、强一致、不可再生、业务核心。

• 最低保护要求：每日全量 + 实时Binlog备份 (RPO < 5min) + 加密 + 跨区存储 + 季度演练。

• 扣分点：无日志备份、存储同集群、保留期 < 30天、无加密。
• PostgreSQL：
• 重要度权重：⭐⭐⭐⭐⭐

• 保护要求：基础同上，必须备份WAL日志，支持PITR。
• Oracle / SQL Server：
• 重要度权重：⭐⭐⭐⭐⭐

• 特殊要求：通常为核心系统，必须符合金融级标准，异地双活/多活。
🔹 NoSQL 数据库

• MongoDB：
• 重要度：⭐⭐⭐⭐

• 特点：副本集架构，需集群感知备份。禁止单节点备份。
• Redis：
• 重要度：⭐⭐⭐ 至 ⭐⭐⭐⭐⭐ (取决于用途)

• 特点：缓存库(⭐⭐⭐) vs 主数据库(⭐⭐⭐⭐⭐)。RDB/AOF持久化必须开启。
• Elasticsearch / Cassandra：
• 重要度：⭐⭐⭐⭐

• 特点：分布式架构，快照仓库(Snapshot Repository) 是唯一正确备份方式。
🔹 中间件 & 消息队列

• Apache Kafka / RocketMQ / Pulsar：
• 重要度：⭐⭐⭐⭐⭐ (消息即数据，是数据流核心)

• 保护要求：Topic 镜像、日志持久化、多副本、跨AZ部署。
• ETCD / Consul：
• 重要度：⭐⭐⭐⭐⭐ (集群大脑，元数据)

• 保护要求：单独定时快照，证书密钥必须一并备份。
🔹 无状态应用 & 网关

• Nginx / Ingress / API Gateway / 前端应用：
• 重要度：⭐⭐ (低)

• 保护要求：仅需备份ConfigMap/Secret/Ingress规则。数据可通过镜像重建，无需数据备份。
🔹 新兴负载 (AI / 大数据)

• Vector DB / Milvus / Qdrant / 大模型权重：
• 重要度：⭐⭐⭐⭐⭐ (高价值资产，训练成本极高，不可再生)

• 保护要求：全量快照 + 版本化管理 + 离线归档。
🟧 分类3：合规与行业标准 (Compliance)
合规项是“硬扣分”，不满足直接降分。
1. 等保2.0 三级要求（通用企业级）：
• 数据备份：应建立本地备份与异地备份机制，定期执行恢复测试。

• 数据安全：传输加密、存储加密、访问控制、审计日志。

• 留存期：核心数据保留 ≥ 6个月，日志 ≥ 180天。
2. 金融行业标准：
• 业务连续性：RTO ≤ 4小时，重要系统 ≤ 30分钟；RPO ≤ 5分钟。

• 两地三中心架构要求。
3. 数据分类分级：
• 核心数据（交易、用户隐私）：最高保护级别。

• 一般业务数据：标准保护。

• 公开数据：基础保护。
🟥 分类4：架构风险反模式 (Anti-Patterns)
识别架构中的天生缺陷，直接影响评分。
1. 单点故障风险：
• PVC 存储在单节点/单AZ，无跨区部署。 → ⚠️ 中高风险

• 单副本 StatefulSet，无高可用。 → ⚠️ 高风险
2. 备份架构风险：
• 备份存储与生产存储属于同一存储集群/同一故障域。 → 🚨 严重风险 (鸡蛋放一个篮子)

• 仅快照无日志：快照窗口间数据丢失无法恢复。 → 🚨 高风险

• 备份保留策略与业务生命周期不匹配。 → ⚠️ 中风险
3. 配置风险：
• 备份未加密，密钥硬编码。 → 🚨 合规风险

• 备份执行用户权限过高/过低。 → ⚠️ 操作风险

# 评分规则
1. 评分范围：0 至 100 分。分数越高代表数据安全与保护状况越好。
- 90-100：优秀。符合金融级标准，架构完美，保护到位，无风险。
- 70-89：良好。满足基本要求，存在少量优化点，低风险。
- 60-69：及格。满足最低要求，但存在明显短板，中风险。
- 0-59：危险。存在重大漏洞、合规违规或架构缺陷，高风险至严重风险。
2. 评分维度（权重）：
- 业务价值与重要度：30% (基于应用类型、数据敏感度、依赖关系)
- 架构高可用：20% (副本、反亲和、跨AZ、存储冗余)
- 保护策略完整性：30% (备份频率、类型、RPO/RPO匹配、保留期)
- 安全性与合规：15% (加密、权限、存储位置、审计)
- 运维可信度：5% (成功率、恢复演练记录)
3. 扣分原则：
- 违反灾备黄金法则（3-2-1）：单次扣10-20分。
- 核心数据库无日志/PITR：直接扣15-25分。
- 备份与生产同存储/同AZ：扣15分。
- 超过6个月未做恢复演练：扣10分。
- 无任何备份：直接 ≤ 30分。
4. 加分原则：
- 跨区域/跨集群复制：+5分。
- 开启不可变存储（WORM）：+5分。
- 自动恢复测试：+5分。
