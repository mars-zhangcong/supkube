## 一、执行摘要

本轮三件事：**PRD-009 从"低风险 UI 词汇重构"长成了带 ImportPolicy CRD + controller 的跨集群后端特性**（Phase 2）；**新增 PRD-011（AI Backup Advisor MVP）**——把我之前对 PRD-003 的 finding（分数可复现、置信度不用百分比、缺失显式建模、本地 Ollama、非自治）直接写成了"三条铁律"，是这套文档里 AI 工程纪律最好的一份；**新增 PRD-012（Call Home）**——隐私默认正确、明确 Blocked 等 Case API 规格。

但有一条**跨文档的回归问题必须先点出来**：**ADR 号台账当初就是为了防撞号而建，现在 ADR-037 / ADR-038 又各自被两处指向不同主题**——台账已把 037 给"数据采集"（PRD-011/012）、038 给"ImportPolicy"（PRD-009），但仍是草稿、本轮未改的 **PRD-008 仍用 ADR-037 指"Activity 持久化存储"、PRD-010 仍用 ADR-038 指"DR Topology SVG 规范"**。台账内部是自洽的，问题在于两份旧草稿没跟着改号，等它们修订时必然撞车。

其余按 PRD 分述。整体方向都对，PRD-011 接近可过，PRD-009 v2 的规范主体扎实但**验收/任务段没跟着 Phase 2 扩**，PRD-012 合理但 Blocked。

### 放行结论速览

| PRD | 结论 | 关键前置 |
|---|---|---|
| **PRD-009 v2** | 方向通过 / 补齐后研发 | G5 §8 DoD + §9 任务段仍是 Phase 1 内容，未覆盖 Import Policy（必补）；G1 "30s vs Kasten 5min=10x RPO" 卖点过度承诺；G2 全局 `backupSyncPeriod` 60s→5min 对无 ImportPolicy 的 BSL 是回归 |
| **PRD-011** | 接近通过（AI 纪律范本） | H1 评分权重/扣分值需版本化 + 专家校准 + 写明依据；H2 "3-2-1/异地"判定需真实 region/provider 元数据；H5 LLM 解释别阻塞同步 60s（分数先返回） |
| **PRD-012** | 方向通过 / Blocked（待 Case API 规格） | I1 默认逐次确认而非预授权自动 + 并入 SECURITY §6 出境白名单；I2 客户身份/多租户标识（无 license server 下如何关联 Case） |

## 二、跨文档：ADR-037 / ADR-038 撞号复发（High，文档/可追溯）

台账（架构设计.md §ADR 号台账，SSOT）当前：

- **ADR-037 = 统一数据采集架构**（CollectionContract + Collector/Server + Canonical DSL + 三档连接）→ PRD-011 / PRD-012
- **ADR-038 = ImportPolicy CRD + Controller** → PRD-009 v2 / PRD-007 §4.4 / #88 / #157-163

但两份**本轮未改的草稿**还引用旧含义：

- **PRD-008** §关联 ADR：`拟 ADR-037（Activity 持久化与 audit event 存储选型）` ← 与台账 037 冲突
- **PRD-010** §关联 ADR：`拟 ADR-038（DR Topology SVG 视觉规范）` ← 与台账 038 冲突

台账本身自洽（037/038 各只指一个主题），问题是 PRD-008/010 在 037/038 被重新分配给新 PRD **之前**就占用了这两个号、之后没跟着改。这正是当初建台账要防的 X2 类问题。**建议**：PRD-008 的"审计存储选型"改用 **ADR-039**、PRD-010 的"DR Topology SVG 规范"改用 **ADR-040**，登记进台账；并在台账"新增 ADR 必须"流程里加一条"占号前先查表、被复用过的旧号不得沿用"。这是低成本但必须做的卫生项，否则 PRD-008/010 一进研发就撞。

## 三、PRD-009 v2 — Import Policy（CRD + Controller）

Phase 2 把 Policy 顶部加了 Action Type 二选一（Snapshot Policy / Import Policy），新增 ImportPolicy CRD + controller + Continuous/Scheduled 子模式 + fingerprint enforce/warn/disabled 三档 + 状态机 + 14 条错误码。CRD/admission webhook/状态机/可观测（observedRPO、nextPollAt）设计都很扎实，fingerprint 三档是对 PRD-007 P3 的好落地，与 §4.4 的分层（算法在 007、用户面在 009、CRD 工程在 ADR-038）划得清楚。

| # | 严重度 | 问题 | 建议 |
|---|---|---|---|
| G5 | **High** | §8 DoD（12 条）+ §9 任务拆分（3.5d）+ §6 Out-of-Scope **仍是 Phase 1 词汇重构的内容**，完全没覆盖 Phase 2 的 ImportPolicy CRD/controller/fingerprint 三档/状态机/错误码。规范主体长了一大截，验收与计划没跟上 = 没有可验证的完成定义。 | 给 Phase 2 补独立 DoD（CRD schema/webhook 校验/状态机转换/三档 fingerprint 行为/RPO 显示/错误码各一条可测）+ 任务估时；Phase 2 的风险评级独立写（不再是"0 迁移风险"，那只对 Phase 1 成立）。 |
| G1 | **Med** | "Poll floor 30s vs Kasten 5min = 10x 更快 RPO" 作为差异化卖点**过度承诺**。本 PRD §4.5.2 自己的 RPO 公式 = `source_backup_interval + import_poll_interval`——RPO 几乎总被**源备份周期**主导。源每小时导出时，import 每 30s 还是 5min 轮询对 ~1h 的 RPO 只差几十秒，却把 BSL LIST API 成本 ×10。 | 卖点改为诚实表述：import poll 低于源导出周期时**无 RPO 收益**；默认 60s/2m，30s 仅在源亚分钟级导出（罕见）时有意义。别用"10x RPO"做头条。 |
| G2 | **Med** | 头表兼容说明把全局 Velero `backupSyncPeriod` 60s **调到 5min** 作兜底，称"无 Import Policy = 退化到 Velero 默认行为，不丢功能"。但这改变了默认值——**没有 ImportPolicy 覆盖的 BSL，RP 可见性从 60s 退到最长 5min**，是行为回归，不是"默认保留"。 | 要么保持 60s 不动、ImportPolicy 叠加在上层（更细的 cluster-id 过滤 + fingerprint）；要么显式声明非 ImportPolicy 的 BSL 现在 5min 同步，并确认无用例依赖 60s。 |
| G3 | **Low** | enforce 模式下 fingerprint（源备份完成后才写）天然也是"备份完成"门；但 warn/disabled 会 import 到源**正在写、尚未完成**的半成品 RP。 | 文档点明：fingerprint 兼作"备份完成"信号，warn/disabled 失去该保护，UI 对无 fingerprint 的 RP 标"可能未完成"。 |
| G4 | **Low** | Action Type Save 后不可改（不同 CRD 类型，合理），但选错只能删重建。 | Save 前明确告警"Action Type 保存后不可更改"。 |

## 四、PRD-011 — AI Backup Advisor MVP

这是 AI 工程纪律最好的一份：分数由 **Go 规则引擎**确定性计算、LLM 只翻译不打分（我 PRD-003 的 finding #2 落地）、置信度 high/medium/low 不用伪精确百分比（finding #3）、缺失数据用 `confirmed|optional|missing|unable_to_confirm|source_conflict` 显式建模、默认本地 Ollama 0 出网、非自治只预填不写。尤其**校准规则**（规则算分>90 但实际无任何成功备份 → 强制 30/CRITICAL）是很到位的灾备常识防呆。

| # | 严重度 | 问题 | 建议 |
|---|---|---|---|
| H1 | **Med** | 评分权重（30/20/30/15/5）与扣分值（-10~-25）是合理但**主观的判断**（Q1 自己在问要不要专家校准）。这套规则正是分数可信度的全部来源，"经得起客户问凭什么"取决于它。 | (1) 规则集**版本化**：输出带 `scoreRulesVersion`，可复现保证是"同输入同规则版本同输出"，历史分数才可解释；(2) 每条扣分/权重写依据；(3) 请灾备专家校准（Q1）后再锁 v1。 |
| H2 | **Med** | "3-2-1 满足度""跨地域""同存储后端单点"这些扣分**依赖准确判定异地/介质多样性**。M3 只采"BSL 数量与类型（local/cloud）"——两个同区域 cloud BSL 不算异地，"cloud"也可能同区域。判错就会误导分数（DR 面板最忌讳）。 | M3 显式采 BSL 的 region + provider；精确定义"异地"（不同 region 且/或 不同 provider）；"同存储后端"按真实 backend 比较。本分数 = PRD-003 应用韧性分（与 PRD-007 集群 Posture 是 P5 已定的两个独立指标，方向一致 ✅）。 |
| H5 | **Med** | `/ai/analyze` 同步 60s 跑完采集+评分+LLM 解释。本地 Ollama 在 CPU 节点生成一段解释常需 10-40s，大 ns 采集+LLM 可能破 60s（Q5 已问转异步）。 | 规则引擎快、是关键产物——**分数+证据先同步返回**，LLM 解释流式/异步补；用户不该被 Ollama 阻塞。 |
| H4 | **Low** | ~30 条知识库上 chroma-go（Q3）对 MVP 偏重，增大 AirGap 镜像。 | MVP 可先 tag 预过滤 + 全量注入；条目过百再引向量库。已加结构化标签预过滤保可解释，可接受。 |
| H3 | **Info** | ADR-037 撞号（见第二章），不影响本 PRD 设计。 | 台账已正确指 037→PRD-011/012，无需改本 PRD，仅 PRD-008 让号。 |

## 五、PRD-012 — Call Home / Auto-Support

隐私姿态正确：默认关闭 + 显式 opt-in + 脱敏预览 + SanitizeReport + 单向出站无入站 + 非自治（只开 Case 给人，不改集群）+ 不开则退回 PRD-011 本地闭环 0 降级。复用 PRD-011 Collector + ADR-033 sanitize，0 重复。明确 Blocked 等 Case API 规格，纪律好。

| # | 严重度 | 问题 | 建议 |
|---|---|---|---|
| I1 | **Med** | Story 3.2 + Q1 的"预授权自动"模式——数据**无每次人工复核**就离开集群。脱敏一旦漏一项即外泄。 | 默认**逐次确认**；"预授权自动"仅作显式高级 opt-in，且 Call Home 载荷字段并入 **SECURITY.md §6 出境白名单**（与 PRD-011 SaaS / PRD-003 同一可审计管线），客户可逐项关。 |
| I2 | **Med** | 出站需让售后系统识别"这是哪个客户/合同"，但项目刻意无 license server（ADR-034）。无客户身份则 Case 无法关联。 | 安装期下发 customer-id/token（一次性，写 K8s Secret），作为 Case API 规格的一部分；在 §8 待补里显式列为设计依赖。 |
| I3 | **Info** | SanitizeReport 预览是亮点。 | 确保预览是**将出境的精确字节**而非摘要，让客户真看到离开的内容（DoD #2 已含）。 |
| I4 | **Info（赞）** | Blocked 状态用得对，规格到位前不开工。 | 保持。 |

## 六、跨 PRD / 架构一致性

- **Collector + Canonical DSL 成为基础设施**：PRD-011 建、PRD-012 复用、PRD-003 是其产品形态——一套采集喂三处，0 重复，架构干净。建议把"Collector/DSL 的 owner = PRD-011，其它引用不另写"在 ADR-037 里钉死。
- **AI 出境治理一致**：PRD-011 SaaS opt-in、PRD-012 Call Home 都走 ADR-033 sanitize + SECURITY §6——延续 T4 治理。建议 I1 把 Call Home 字段也并入 §6 出境白名单，使三处（Advisor/MCP/CallHome）共用一张白名单。
- **Score 口径**：PRD-011 的分 = PRD-003 应用韧性分（per-ns，5 业务/架构维度），与 PRD-007 集群 Posture 分是 P5 已定的两个独立指标——本轮 PRD-011 与该决策一致 ✅。INDEX「Score 口径」🟡 仍挂着的是 PRD-010 的"层数×20 当安全百分比"那层，与本轮无关。
- **ADR 撞号**：见第二章，是本轮唯一的横切硬伤。
